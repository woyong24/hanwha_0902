# 0911 AI API / LangChain 핵심 정리

## 1. 전체 흐름

AI API를 사용할 때 기본 흐름은 다음과 같다.

```text
사용자 질문
↓
LLM 객체
↓
API 요청
↓
OpenAI / Gemini 모델
↓
응답 반환
↓
Python에서 결과 출력
```

---

## 2. LLM 객체 생성

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="gpt-5-nano",
    temperature=0.1,
    max_tokens=2048
)
```

`ChatOpenAI()`는 사용할 AI 모델과 옵션을 설정한 객체를 만든다.

- `model_name` : 사용할 모델
- `temperature` : 답변의 다양성 정도
- `max_tokens` : 최대 출력 토큰 수

`max_tokens=2048`이라고 해서 무조건 2048토큰을 사용하는 것은 아니다.  
최대 2048토큰까지 출력할 수 있다는 의미이다.

---

## 3. invoke()

```python
question = "안녕하세요"

response = llm.invoke(question)

print(response.content)
```

`invoke()`는 AI에게 질문을 보내고 완성된 답변을 한 번에 받는다.

```text
llm
↓
invoke(question)
↓
response
↓
response.content
```

`response`는 사용자가 정한 변수명이다.

`response.content`는 실제 AI 답변 내용이다.

---

## 4. stream()

`stream()`은 답변 전체를 기다리지 않고 생성되는 내용을 조금씩 받아온다.

```python
question = "안녕하세요"

response = llm.stream(question)

for token in response:
    print(token.content, end="", flush=True)
```

각 코드의 의미:

```python
for token in response:
```

응답 조각을 하나씩 가져온다.

```python
token.content
```

응답 조각에서 실제 텍스트만 가져온다.

```python
end=""
```

출력할 때 줄바꿈하지 않고 계속 이어서 출력한다.

```python
flush=True
```

내용을 모아두지 않고 즉시 화면에 출력한다.

즉 ChatGPT처럼 답변이 실시간으로 생성되는 모습을 보여줄 수 있다.

```text
invoke()
질문 → 기다림 → 완성된 답변

stream()
질문 → 답변 조각 → 답변 조각 → 답변 조각 → 완료
```

## 5. 스트리밍 답변 저장

스트리밍으로 받은 조각들을 하나의 문자열로 합칠 수도 있다.

```python
final_answer = ""

for token in response:
    final_answer += token.content
```

`+=`는 기존 문자열 뒤에 새로운 문자열을 계속 붙이는 것이다.

```python
final_answer += token.content
```

는 다음과 같은 의미이다.

```python
final_answer = final_answer + token.content
```

## 6. response_metadata

```python
response.response_metadata
```

AI가 생성한 답변 외의 부가 정보를 확인할 때 사용한다.

```text
response.content
→ 실제 AI 답변

response.response_metadata
→ 모델 정보, 종료 이유, logprob 등의 부가 정보
```

---

## 7. Logprob

`logprob`는 모델이 특정 토큰을 얼마나 높은 확률로 선택했는지를 나타내는 값이다.

```text
0에 가까움
→ 선택 가능성이 높음

큰 음수
→ 선택 가능성이 낮음
```

예를 들어 모델이 다음 단어를 선택할 때:

```text
"나는 밥을 ___"

먹었다 → 확률 높음
마셨다 → 확률 중간
달렸다 → 확률 낮음
```

이러한 선택 확률을 로그 형태로 표현한 것이 `logprob`이다.

## 8. bind()

옵션은 객체를 만들 때 바로 넣을 수 있다.

```python
llm = ChatOpenAI(
    model_name="gpt-5-nano",
    logprobs=True
)
```

또는 기존 객체에 `bind()`로 옵션을 추가할 수도 있다.

```python
llm = ChatOpenAI(
    model_name="gpt-5-nano"
)

llm_with_logprob = llm.bind(
    logprobs=True
)
```

```text
ChatOpenAI(..., 옵션)
→ 객체를 만들 때 옵션 설정

llm.bind(옵션)
→ 기존 객체에 옵션을 묶은 새로운 실행 객체 생성
```

원래 `llm` 객체는 그대로 유지된다.

## 9. API 호출과 토큰

다음은 객체만 만드는 것이므로 실제 AI 호출이 아니다.

```python
llm = ChatOpenAI(...)
```

실제 API 호출은 다음과 같은 부분에서 발생한다.

```python
llm.invoke(question)
```

또는

```python
llm.stream(question)
```

같은 질문을 다시 요청하면 새로운 API 호출이므로 토큰도 다시 사용된다.

`stream()`의 `for`문이 한 번 반복될 때마다 새로운 요청을 보내는 것은 아니다.  
한 번의 요청에서 생성되는 답변을 여러 조각으로 나눠 받는 것이다.

## 10. Gemini 토큰 사용량 확인

Gemini에서는 `usage_metadata`를 통해 사용한 토큰을 확인할 수 있다.

```python
print(response.usage_metadata)
```

주요 값:

```text
prompt_token_count
→ 입력 토큰 수

candidates_token_count
→ 출력 토큰 수

total_token_count
→ 전체 토큰 수
```

필요한 값만 출력할 수도 있다.

```python
print("입력 토큰:", response.usage_metadata.prompt_token_count)
print("출력 토큰:", response.usage_metadata.candidates_token_count)
print("전체 토큰:", response.usage_metadata.total_token_count)
```

## 11. API Key와 환경변수

API Key는 코드에 직접 작성하지 않고 환경변수나 `.env`로 관리하는 것이 안전하다.

```python
import os

api_key = os.getenv("GEMINI_API_KEY")
```

`os.getenv()`는 현재 Python 실행 환경에서 해당 환경변수를 가져온다.

`.env` 파일에는 API Key가 들어갈 수 있으므로 GitHub에 올라가지 않도록 `.gitignore`에 작성한다.

```gitignore
.env
```

실제로 무시되는지 확인:

```bash
git check-ignore -v 260911/.env
```

## 12. requirements.txt

`requirements.txt`는 프로젝트에 설치된 Python 패키지와 버전을 기록하는 파일이다.

현재 가상환경 기준으로 생성:

```bash
pip freeze > requirements.txt
```

예:

```text
google-genai==2.23.0
langchain-openai==1.6.2
openai==...
```

다른 환경에서 동일한 패키지를 설치할 때:

```bash
pip install -r requirements.txt
```

즉 `requirements.txt`는 프로젝트 실행 환경을 다시 만들기 위한 패키지 설치 목록이다.
